Getting the input list right matters more than getting it complete. Guessing extra inputs is worse than omitting real ones.

This is how we know the method works, and where it stops working. We take a hundred real unit processes, aggregate them the same way BAFU does, throw the input list away, and hand the algorithm a candidate input list of deliberately varying quality. Every row is a case where the fit has to set the amounts, which is exactly the S2 and S3 situation; an S1 report needs no fit at all. Given the complete list, every flow is recovered; given ranges as well, 761 of 803 amounts land within twenty percent. The punchline is the bottom rows. A list that merely omits its minor lines still reaches ninety-one percent. A padded list, the same true inputs plus ten plausible but wrong processes, collapses to sixty-three percent and still hands a material amount to five inputs that were never in the process. With no list at all it is six percent and eighty-one invented inputs. So over-proposing is worse than under-proposing, which matters because over-proposing is exactly what an LLM does when asked to guess an input list. One limit to say out loud: these synthetic targets share their background data with the rebuild; the real originals were computed on older background data, and that drift is not tested here. Be ready for one question: at ten cases the padded row read ninety-five percent and we had it the other way round; at a hundred cases it is sixty-three. The ten-case sample happened to contain easy cases, and re-scoring the hundred-case run on those same ten reproduces ninety-five exactly. That is why we ran a hundred. A note on the hundred percent: we only score the flows the calculation actually determines. About a hundred and twenty of the eighteen hundred flows per process come out of the sparse solve as round-off, so they carry no information and are excluded and counted separately. Genuine trace emissions like dioxins stay in.
