Reading a printed table is the rare case, not the normal one. Everything else has to be rebuilt from an existing unit process of the same product, or from chemistry.

The first job was deciding what to work on, and that started with counting. The ecoSpold export marks 101 datasets as system processes, and we started there. That flag turns out to be incomplete. If you ignore the flag and ask a structural question instead — does this dataset consume anything that is actually a production input, or only waste-treatment services and a plant unit — you find 37 more. Those are the old APME and PlasticsEurope eco-profiles: styrene, benzene, butadiene, the nylons, ABS, polycarbonate, the isocyanates. They confirm it in their own metadata, which the test never reads: their includedProcesses field says aggregated data from raw material extraction until delivery at plant. So we found 138, not 101, and there may be more: the structural test only catches datasets with no production input at all, so a partly aggregated dataset would still slip through. The bottom band is the uncomfortable part. Fifty-three cite no report we have. Seventy-three cite a report that is in the bundle but never prints an inventory table — it gives a process description, or an impact result, and that is all. Only twelve hand us a table we can transcribe. So a method that only knows how to read tables would finish with twelve datasets. That is why most of what comes next is not transcription.
