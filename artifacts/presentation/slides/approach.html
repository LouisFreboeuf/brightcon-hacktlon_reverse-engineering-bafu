Step two · the method

Read the report, then pick a route

How much does the report give away?

S1  It prints the unit process table. Copy it.

S2  It is confidential, but a unit process for the same product in another country exists. Reuse its structure.

S3  Only a process description. Derive the input list from chemistry.

S4  Nothing but the aggregated flows. Guess — never on its own.

Where amounts are still missing, we solve for them

A report often names an input without a quantity, or gives a range. But we do know the aggregated flows the unit process has to reproduce.

Known: the aggregated flows  ·  Known: the input list
Unknown: the amounts  →  fit them

Each candidate input carries its own known inventory, so this is a least‑squares fit over ~1,800 elementary flows at once — no impact score, no weighting of climate against toxicity.

Each rebuilt unit process also keeps a residual block, so it still reproduces the system process exactly while we improve it

The pipeline is the same for every dataset: find all system processes, pull their metadata and their cited PDF, read what the report actually contains, decide which of four routes applies, and only then fit whatever amounts are still missing. The optimisation is the part worth explaining slowly: we are not inventing data out of nothing. We know the answer the unit process has to produce, because the system process gives us the aggregated flows. We know, from the report, which inputs went in. What we solve for is the amounts. The last point on the right matters for credibility: we never compare impact scores, we compare all eighteen hundred elementary flows, so we cannot accidentally trade climate performance against something else.
