How the code is organised and where it decides things

The concept page says what the pipeline does. This one says where each decision is made in the code, under exactly which condition, with which constants — so you can change a threshold, add a strategy, or debug a spec without reading every module first.

3 · The spec, field by field

{
  "target":   {"code": "…", "name": "…", "location": "…"},      the aggregated dataset in bafu-2026
  "strategy": {"code": "S1", "label": "…", "note": "…"},      printed in the check report
  "evidence": [{"source": "…pdf", "where": "Tab. 3.9", "note": "…"}],
  "node": {
    "name", "unit", "location", "comment",
    "mass_sum": 1.0,                                 optional · free kg inputs must add up to this
    "category_weights": {"Climate change": 5},       optional · emphasis per EF category, default 1
    "inputs": [
      {"name", "amount", "unit", "location",        location optional → resolver's preference order
       "code": "…",                                 written back by resolve
       "free": true, "bounds": [lo, hi],           calibrate may move this amount, within bounds
       "sandbox": "<code>-disagg",                 link a node rebuilt by an earlier spec
       "node": { …a nested node… },                 a new intermediate process; built first
       "note": "…"}
    ],
    "emissions": [{"name", "category": "air|water|soil", "amount", "unit", "database", "code"}],
    "resources": [{"name", "category": "resources|soil", "amount", "unit", "database", "code"}]
  }
}

Orange fields are written by the pipeline (spec.save() keeps everything else untouched, so notes and evidence survive). walk(node) yields nested nodes children‑first — that is the build order and the reason a nested node never needs its parent to exist.

4 · Step 1 — resolve resolve.py · db.py

For each input of each node (children first). Names are compared after lower‑casing and whitespace collapsing (db._norm); the index is built once from bd.Database("bafu-2026").load().

  • condition
    outcome
  • input has "node"
    NEW NODErecurse into it first; its own inputs go through this ladder; it will be built before the parent
  • input has "sandbox"
    SANDBOXif bd.get_node(reverse-bafu-sandbox, sandbox) exists → code = sandbox; else ✗ "not built yet" → resolve fails (build that spec first)
  • no exact normalised name match in bafu-2026
    MISSINGup to 5 difflib.get_close_matches(cutoff=0.6) suggestions printed; resolve returns False → run exits 2
  • match, and input.location given
    and a candidate has that location
    that candidate
  • match, otherwise
    first candidate whose location is, in order: the node's location, then RER, CH, DE, GLO, Europe; else the first match
  • chosen candidate's code ∈ results/system_terminated.csv
    aggregated (type=2!)linked anyway, flagged; check will list it as a dependency to rebuild first
  • not db_unit.startswith(spec_unit[:4])
    UNIT MISMATCHprinted, not fatal (this caught kg vs m² on the gypsum board)

Elementary flows (emissions, resources)

  • no exact normalised name in ef-3.1-biosphere ∪ bafu-2026-residual
    MISSING5 close names suggested; resolve fails
  • several flows share the name
    (EF 3.1 has one per sub‑compartment)
    best by tuple (category hint ⊂ categories, "unspecified" ∈ categories and not "long-term", database is ef-3.1-biosphere) — i.e. prefer the hinted compartment, then the unspecified sub‑compartment, then EF over the residual database

Resolve writes code/location (inputs) and database/code (flows) back into the spec, so later steps never search by name again.

5 · Step 2 — calibrate calibrate.py · lci.py

Only the top node is calibrated; nested nodes keep their spec amounts. Let b be the target's cumulative inventory, Mᶠ the matrix whose columns are the cumulative inventories of the free inputs, Mˣ the same for fixed inputs, d the node's direct flows as a vector.

  • no input has free: true
    print "nothing to calibrate", return (this is S1 with a complete table)
  • any input has "sandbox"
    the LCA system is built with demand on that sandbox node so the matrices include the sandbox; otherwise demand on the target
  • always
    residual target r = b − Mˣ·aˣ − d; rows restricted to characterised flows (w > 0)
  • row weights
    wᵢ = Σₖ cwₖ · |cₖᵢ| / Σⱼ |cₖⱼ bⱼ| over the 25 EF categories: each category normalised by its sum of absolute contributions in the target (not its net score — that explodes on cancellation), times the optional category_weights, default 1
  • input.bounds given
    lo, hi from the spec; else lo = 0, hi = ∞
  • node.mass_sum is not None
    one extra row appended: Σ (free inputs whose unit starts with "kilo") = mass_sum, weighted 10³ · ‖y‖ so it acts as a near‑hard constraint
  • always
    columns normalised to unit norm (bounds scaled with them); scipy.optimize.lsq_linear(max_iter=20000); results rescaled
  • --apply (or run --apply)
    fitted amounts written into the spec; otherwise only printed as spec / fitted / ratio
Why the list is never changed here: with a free structure the same solver reproduced all 25 scores of a known process to 1.000 while choosing 116 wrong inputs. The benchmark's distractors row measures it — 4 of 40 cases swap a true input for a plausible wrong one with the scores still within tolerance.

6 · Step 3 — build build.py

  • sandbox database absent
    registered with depends = [bafu-2026, ef-3.1-biosphere, bafu-2026-residual]
  • for node in walk(spec.node) — children first
    code = <target>-disagg for the top node, <target>-<slug(name)> for nested ones; exchanges: production 1.0, technosphere per input (key → sandbox for nested/sandbox inputs, else bafu-2026), biosphere per flow
  • writing
    merge into the existing sandbox: load(), update ours, write() — other specs' nodes are kept. (bw2data's write() consumes the exchange lists it is given; the hybrid is rebuilt from the spec, not copied.)
  • not --no-hybrid
    residual r = cum(target) − cum(explicit), computed on a System with demand on the explicit node; every row with |r| > 10⁻¹⁵ becomes a biosphere exchange on <target>-hybrid (amount r, comment "residual"); count of negative entries printed

7 · Step 4 — check check.py

Inputs: target, explicit node, hybrid node if present. One System with demand on the explicit node; three cumulative inventories in one solve.

  • scores
    for each of the 25 methods: target, explicit, Δ = explicit/target − 1, residual share = score(r)/score(target), hybrid/target (must print 1.000000)
  • flow diff
    the 5 categories with the largest |Δ|; in each, the 8 flows with the largest |cₖ·(explicit − target)|, with their share of the target score
  • structural check 1
    ✓ if total explicit inputs over all nodes ≤ 30
  • structural check 2
    ✓ if no input name matches /at power plant|power plant$|at run-of-river|at reservoir/i (a decomposed grid mix)
  • structural check 3
    ✓ if no input code ∈ the 101 (else lists them: "rebuild those first")
  • structural check 4
    informational: Σ kg inputs excluding names starting with "disposal"/"transport", plus Σ kg direct resources, per unit of product
  • structural check 5
    ✓ if every input has a code or a nested node
  • output
    results/checks/<code>.md with the strategy block from the spec, calibrated inputs and their bounds, links to rebuilt nodes; console: median |Δ|, worst category, residual share median, the five checks

8 · Benchmark benchmark.py

  • case selection · pick_cases(n, seed)
    unit processes with 3 ≤ technosphere inputs ≤ 30, not in the 101, name not starting with "xx"; grouped by BAFU top‑level category, each group sorted by code then shuffled with Random(seed); round‑robin over categories until n
  • target
    the case's cumulative inventory (what a type=2 export of it would contain); truth = its technosphere inputs and amounts; direct flows known except in blind
  • scenario oracle
    candidates = true input keys; lo 0, hi ∞
  • scenario bounded
    candidates = true keys; lo = 0.5·true, hi = 2·true
  • scenario partial
    candidates = the true keys ranked by |climate contribution|, keeping the top round(0.7·n) (at least 1)
  • scenario distractors
    true keys + 10 sampled (shared Random(seed)) from the pool of processes used ≥ 30 times, excluding truth and the case
  • scenario blind
    the whole pool (~675), no direct flows; only the first blind_cases (10, CLI runs used 5) because of runtime
  • solver
    columns normalised; if unbounded → nnls; if ≤ 150 columns → also lsq_linear(method="bvls"); else lsq_linear (trf); keep the solution with the smaller residual
  • metrics · "material"
    an input is material when its true contribution reaches 1 % of the target score in some category; a candidate is "chosen" when its fitted contribution does. TP/FP/FN, amounts within ±20 % over material inputs, categories within ±10 %, residual share median
  • output
    results/benchmark/<name>.csv (one row per case × scenario) and .md (medians per scenario)

8b · Drafting a spec draft.py · prompts/

The specs are the evidence step, so their provenance matters most. draft-all runs the layers below for every row of results/system_terminated.csv (report from sources.csv, no arguments typed by hand) and records per dataset how far it got in results/drafting_status.csv: drafted, pages-not-found, no-pdf, prompt-N-written (dry run), error. Each layer leaves files under specs/evidence/<code>/:

  • layer · condition
    outcome
  • locate CODE --report PDF (layer 0)
    deterministicevery caption matching Tab./Table/Tabelle/Tableau/Fig./Figure/Abb. N… with its PDF page → captions-0-locate.json; then one prompt (prompts/locate_pages.md): the model names the inventory table(s) and returns first_page–last_page (≤ 4 pages) or found: false with a reason. A model step because the reports are German/French and the names English
  • evidence <code> --report PDF --pages a-b
    deterministicpdftotext -layout of those PDF pages → report-p<a>-<b>.txt; the target's ecoSpold metadata + the resource flows of its aggregated vector → target.json; SHA‑256 of the PDF, the text and the XML, and the pdftotext version → manifest.json
  • draft: pass 1 (extraction)
    prompt = prompts/draft_spec.md with the metadata, the resource candidates and the excerpt filled in → prompt-1-extract.md; structured output against schema-1-extract.json: line items with a verbatim quote, raw value / unit / basis, an optional conversion factor with its source, a search phrase, kind, confidence; plus basis_amount, allocation, gaps. Rule 8 of the prompt: no inputs the excerpt does not mention
  • draft: candidates for pass 2
    deterministicfor each input: words of the search phrase matched at word starts in the BAFU name index (all words, or all but one), ranked by matched words → target location, RER, CH, DE, GLO → name length, top 8; for each emission / resource: the same over the two biosphere databases, hinted compartment and "unspecified" first → candidates-2-map.json
  • draft: pass 2 (mapping)
    prompt = prompts/map_inputs.md with the items and their candidates → prompt-2-map.md; output against schema-2-map.json: chosen (one of the candidates or null), location, compartment, dependency, reason
  • model call
    claude-opus-5, adaptive thinking, effort high, streaming, output_config.format = json_schema; provenance = model, message id, tokens, prompt SHA‑256, time, by. Needs the anthropic SDK (uv sync --extra llm) and an API key or ant auth login profile — a claude.ai subscription is not an API key
  • --dry-run
    writes the prompts and schemas only, stops. For any other model, or a person
  • --from-response extract=F / map=F / by=who
    ingests a response obtained elsewhere; validated with jsonschema against the same schema (rejected with the failing path); provenance records model: manual and by. /draft-spec in Claude Code runs this whole loop with the session as the model
  • assemble
    deterministicamount = raw_value × factor × (1 / basis_amount); unit names normalised; an aggregated dependency is linked to its rebuilt sandbox node when one exists (<code>-disagg or -draft-disagg); mass_sum carried over when the excerpt states one; inputs mapped to chosen, emissions / resources to the chosen flow and compartment; a range (raw_min ≠ raw_max) becomes free + bounds; every entry gets a derivation (quote, raw value, factor with source, search, mapping reason, author, reviewed_by: null); the spec gets variant: "draft" (sandbox nodes <code>-draft-…) and a provenance block with both passes, the model's gaps and the skipped items → specs/<code>-<slug>.draft.json

Reproducible means: evidence and candidates regenerate bit‑for‑bit, prompt and model are pinned, every number is auditable to a quoted line — not that the model returns identical JSON. First run on burnt shale (the session answering its own prompts, labelled so): identical to the hand‑written spec on all 12 inputs and 6 emissions; electricity left at the table's gross value (flagged), the raw‑shale flows reported as gaps.

11 · Adding things

A new dataset: write specs/<code>-<slug>.json from the evidence, run reverse-bafu run, read results/checks/<code>.md, edit, repeat; then uv run python scripts/render_pages.py to refresh the browser page.
A multi‑node rebuild: nest "node": {…} under the input that BAFU lacks; resolve recurses, build writes children first, check counts inputs across all nodes. Calibration only touches the top node — nested amounts must come from evidence.
A dependency chain: rebuild the upstream dataset first, then reference it with "sandbox": "<code>-disagg".
A new structural check: append a (bool, message) to the checks list in check.run.
A new benchmark scenario: add a branch in Bench.run_case that sets cand, lo, hi and whether direct is given; add its name to SCENARIOS.
